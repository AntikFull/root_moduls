# История изменений

Диагностика на OnePlus PJA110 / ColorOS 16 / Android 16 / KernelSU Next
(ядро 5.15, без `xt_connbytes` → SMART_ACTIVE).

### Обход перестал быть «только для YouTube»

- Стратегия, прошедшая активный подбор, теперь применяется ко **всему**
  TLS/443-трафику. Раньше выбранный профиль подставлялся исключительно в
  `--hostlist=smart_youtube.list`, а все остальные сайты обслуживал
  фиксированный `SMART_COMPAT_GENERAL`, который никогда не проверялся.
  `SMART_COMPAT_GENERAL` остался вторым профилем-запаской (HTTP/80 и прочее).
- Активный probe проверяет две группы контрольных хостов: `GENERAL`
  (discord.com, instagram.com, x.com) и `GOOGLE` (YouTube/googlevideo).
  Раньше проверялся один YouTube, поэтому на сети, где YouTube и так
  открывается, «проходил» первый же кандидат независимо от того, чинит он
  хоть что-нибудь. Списки настраиваются: `AUTO_PROBE_HOSTS_GENERAL` /
  `AUTO_PROBE_HOSTS_GOOGLE`.

- Прогон начинается с замера **без обхода**. Он отвечает на вопрос, нужен ли
  обход этой сети вообще, и отделяет хосты, которые не чинятся никаким
  desync, от тех, что чинятся.
- Кандидат оценивается по числу починенных хостов, а не по принципу «прошли
  все». Прежнее правило означало, что один хост, заблокированный по IP
  (Discord в РФ), обнулял результат для всех кандидатов сразу: модуль писал
  «все кандидаты не прошли» и вслепую откатывался к профилю по умолчанию,
  хотя рабочая стратегия среди кандидатов была.
- Кандидат, ломающий то, что работало без обхода, отбрасывается независимо
  от счта. Кандидат, чей desync отвергнут nfqws2 (ошибки lua в логе), тоже.
- Победитель  стратегия с максимальным счтом; при полном совпадении
  перебор прекращается досрочно. Статус `PARTIAL` в health/WebUI означает
  «часть контрольных хостов не чинится обходом в принципе».
- Замер на реальной сотовой сети: базовая линия 0/6, COMPAT_FAKE и SIMPLE_ALT4
  чинят 4/6, SPLIT_SAFE и два PADENCAP-профиля — 0/6. Выбран COMPAT_FAKE.
  Старая логика в той же ситуации не выбирала ничего.

### DIRECT: нулевое потребление на нефильтрованной сети

- `strategies/strategy_1` — новый профиль `DIRECT` (`# MODE=DIRECT`), первый
  кандидат подбора. Если сеть проходит весь probe без обхода (типичный
  домашний Wi-Fi), модуль **не создат ни одного правила netfilter и не
  запускает nfqws2**: ни очередей в userspace, ни QUIC-REJECT.
- Смена сети возвращает обход автоматически: результат кэшируется отдельно на
  каждую Wi-Fi/сотовую сеть, watcher перезапускает подбор по netlink-событию.
- Отключается через `AUTO_ALLOW_DIRECT="0"`.
- `health.env`/WebUI/`zapret2-control json-status` отдают отдельный признак
  `direct`; health-watcher больше не считает отсутствие nfqws2 сбоем.
- Профиль по умолчанию до первого удачного probe — `strategy_2` (первая
  реальная стратегия), чтобы новая сеть не осталась без обхода.

### Энергоэффективность

- `vpn-watch.sh` больше не опрашивает флаг событий каждые 2 секунды. Цикл
  блокируется в ядре на `read -t` по FIFO от `ip monitor` и просыпается на
  фактическом rtnetlink-событии. Поддержка `read -t` определяется на старте,
  иначе используется прежний sleep-цикл.
- `ip monitor` подписан на `link address route` вместо `all`: события neigh
  (ARP) на людном Wi-Fi больше не будят watcher десятки раз в минуту.
- Резервная проверка ролей сначала сравнивает дешвую sysfs-подпись
  интерфейсов и запускает `dumpsys connectivity`/`dumpsys tethering` только
  когда она изменилась.
- Интервалы приведены к событийной модели: `VPN_WATCH_INTERVAL` 2 → 20,
  `VPN_ROLE_RECHECK` 30 → 120, `VPN_VERIFY_INTERVAL` 60 → 300,
  `HEALTH_WATCH_INTERVAL` 30 → 60. При обновлении значения подтягиваются.

### Две штатные стратегии были нерабочими

Проверено прогоном каждого профиля через отдельную очередь с `--debug`:

- `strategy_5` (USER_PADENCAP_TLSMOD) — у `--lua-desync=fake` не был задан
  `blob=`, а он обязателен (`zapret-antidpi.lua:454`, `fake: 'blob' arg
  required`). Каждый fake-пакет валился с ошибкой lua, desync не применялся.
  Добавлен `blob=0x00000000`, как в соседнем `strategy_6`.
- `strategy_7` — использовал маркер позиции `midsni`, которого не существует.
  Валидный список nfqws2/zapret2: `method, host, endhost, sld, endsld,
  midsld, sniext` (плюс абсолютные и отрицательные смещения). В бинарнике
  `nfqws2` строки `midsni` нет вообще, отсюда `bad marker list`. Заменн на
  `midsld`, профиль переименован в `USER_MIDSLD_MD5`. После правки стратегия
  впервые отработала успешно.
- `pos=1,5` при этом полностью корректен — числовые маркеры поддерживаются,
  `strategy_6` с ним работает без ошибок.
- Кандидат, чей desync отвергнут nfqws2, теперь помечается `INVALID_ARGS` и
  не участвует в выборе, даже если пакеты «прошли» немодифицированными.

### Совместимость с toybox (затрагивает все прошивки на Android 10+)

- `grep` из toybox не понимает `\|` в базовых регулярках, а модуль считал им
  строки во всех списках: `grep -cv '^[[:space:]]*\(#\|$\)'` возвращал число
  строк в файле целиком, вместе с комментариями. Из-за этого WebUI и
  `health.env` показывали завышенные счтчики (для `smart_youtube.list`  16
  вместо 13 доменов, аналогично для apps/exclude-списков). Все такие места
  переведены на `grep -E`.

### Правила и UID

- Устранена генерация правил для несуществующих UID вторичных профилей.
  `packages.list` — общесистемный файл и не знает, в каких профилях пакет
  установлен, поэтому для ColorOS MultiApp (user 999), рабочего профиля и
  второго пользователя создавались правила вида `--uid-owner 99910447` для
  не установленных там приложений. Теперь профиль проверяется по каталогу
  данных `/data/user/<id>/<pkg>`. На тестовом устройстве число правил в
  `ZAPRET2_MANGLE` сократилось вдвое (10 → 5).

- Добавлена файловая очередь пользовательских AUTO-стратегий: `strategy_1`,
  `strategy_2` и далее в естественном числовом порядке без жсткого лимита.
- Стартовый набор расширен до шести профилей: COMPAT_FAKE, SIMPLE_ALT4,
  SPLIT_SAFE и три пользовательских варианта PADENCAP/MD5/MIDSNI.
- Реализован безопасный парсер многострочных аргументов nfqws2 без `source` и
  `eval`; служебные параметры процесса запрещены, symlink игнорируются.
- Коротким стратегиям автоматически добавляется стандартная TLS/443-обвязка.
- Подпись каталога стратегий включена в ключ сетевого кэша и health-состояние:
  изменение порядка или содержимого вызывает новый подбор/быстрый reload.
- Пользовательский каталог стратегий сохраняется при обновлении без перезаписи.
- WebUI показывает число и порядок файлов, имя активной стратегии и статус AUTO.
- COMPAT_FAKE поднят на первое место по умолчанию, SIMPLE_ALT4 — на второе.
- AUTO переведн на фактическую Android default-сеть и dual-stack DNS/probe.
- Добавлен стабильный per-network кэш с отдельным TTL для Wi-Fi и мобильных сетей.
- Переключение профиля выполняется без полной пересборки firewall/UID-правил.
- Уменьшена нагрузка watcher-циклов и устранены event storms при смене сети.
- Исправлены запуск после перезагрузки, кнопки WebUI SMART/AUTO и согласованность
  `health.env`, WebUI и `COMPAT_NOTES` после раннего состояния NO_NETWORK.
- Проверена миграция старых SIMPLE/AUTO-настроек в SMART_ACTIVE.
