# Список изменений Nfqttl eCubz v15.1.5 (1515)

- **Auto VPN Tethering переведён на отдельную module-owned IPv4 routing table:** Android/VPN table используется только для подтверждения активного VPN, а forwarded-трафик раздачи получает собственный `default dev tun/wg/awg` маршрут. Это убирает зависимость от UID/fwmark policy routing Android.
- **Мгновенное переключение без рестарта хотспота:** при активной раздаче watchdog проверяет VPN-состояние раз в 1 секунду; VPN ON создаёт route/rules/NAT, VPN OFF удаляет только module-owned state и сразу возвращает Direct Mode.
- **Безопасный ownership cleanup расширен на route table:** в `.vpn_tether_rules` теперь сохраняется `ROUTE4|table|dev|default`, удаляется только созданный модулем default route.
- **Health-check усилен:** проверяется не только `ip rule`, но и фактический lookup собственной tether-table через активный VPN-интерфейс.
- **Маршрут самого телефона не изменяется:** policy rule применяется только к `iif` активных downstream-интерфейсов.

# Список изменений Nfqttl eCubz v15.1.4 (1514)

- **Исправлено определение виртуальных интерфейсов точки доступа (`wlan2`, `ap0`):** чтение `/sys/class/net/<iface>/operstate` обрабатывает состояния `up`/`down`, а при пустом, unknown значении или недоступности файла для чтения выполняет надёжный fallback на проверку `ip link show state UP`.
- **Исключение конфликтов переменных при парсинге маршрутов ядра:** переменные внутреннего цикла `while read -r _r_if _r_dst ...` изолированы от контекста функции `get_active_tether_ifaces`, исключая потерю распознанных интерфейсов.
- **Точное разделение Wi-Fi Uplink и Wi-Fi Hotspot:** активный шлюз выхода телефона в интернет (`_host_egress4` / `_host_egress6`) гарантированно исключается из списка клиентов раздачи, обеспечивая работу режима Wi-Fi Repeater / Wi-Fi Bridge через VPN.
- **Двунаправленная маршрутизация и NAT в VPN:** проверена и подтверждена сквозная пересылка трафика клиентов раздачи в туннель `tun0` с сохранением фиксации TTL=64 / HL=64.
- **Синхронизация версий:** обновлён резервный fallback `MOD_VER` в `customize.sh` до `v15.1.4`.

# Список изменений Nfqttl eCubz v15.1.1 (1511)

- Безопасный ownership cleanup Auto VPN: удаляются только собственные policy rules/chains.
- Убраны глобальные sweep `pref 3000`, TCPMSS и IPv6 DROP.
- Исправлено определение downstream: Wi-Fi uplink с default route не считается tether client.
- Auto VPN apply получил post-validation и rollback при partial failure.
- VPN table теперь требует реальный default route через VPN interface.
- FORWARD/NAT/blocklist scope сужен до реально активных downstream interfaces.
- Hardcoded DNS 1.1.1.1 отключён; DNS override теперь явный через `vpn_dns_server`.
- Watchdog проверяет critical jumps/ruleset и пытается repair, а не только daemon/queue.
- Диагностика mixed Native/NFQUEUE и queue-6464 стала точнее.
- Upgrade blocklist сохраняет backup и отключает legacy NCSI/captive/NTP строки, способные давать "без интернета".

# Список изменений Nfqttl eCubz v15.1.0 (1510)

- **Интегрирован Auto VPN Tethering (Всё-в-одном):** автоматическое перенаправление трафика подключенных по Wi-Fi / USB / Bluetooth устройств в активный VPN-туннель (`tun0`, `wg*`, `awg*`, `vpn*`).
- **Устранено ложное определение Native TTL/HL:** проверка таргетов ядра переведена с userspace help на реальную вставку правил в тестовую цепочку ядра; при отсутствии нативной поддержки автоматически включается NFQUEUE fallback.
- **Изолированная цепочка `nfqttl_vpn6_fwd`:** устранены глобальные правила `IPv6 DROP`, блокировка IPv6 ограничена клиентами раздачи в режиме VPN и полностью удаляется при выключении VPN и uninstall.
- **Устранена утечка `TCPMSS`:** фиксация MSS изолирована внутри цепочки `nfqttl_vpn_fwd` и очищается автоматически.
- **Отслеживание смены таблицы VPN (`LAST_VPN_TABLE`):** watchdog отслеживает смену номера таблицы маршрутизации туннеля (`1034` -> `1035` -> `1036`) и своевременно перестраивает маршруты.
- **Безопасный поиск таблицы VPN в `get_vpn_table()`:** привязка осуществляется строго по наличию маршрутов через VPN-интерфейс.
- **Разделение NAT:** интерфейс `tun+` исключен из сотового `CELL_IFS`, устраняя дублирование маскарадинга.
- **Синхронизация версий:** обновлен `update.json` до версии v15.1.0 (1510).

# Список изменений Nfqttl eCubz v15.0.4 (1504)

- Исправлен mixed-ingress: IPv4 и IPv6 теперь независимо выбирают native/NFQUEUE/none, поэтому отсутствие только одного из TTL/HL targets больше не отключает fallback для второго семейства.
- `tether_up()` теперь учитывает IPv6 default route, уменьшая ложные срабатывания на IPv6-only uplink.
- Watchdog после 50 подряд неудачных рестартов делает 300-секундный cooldown и продолжает наблюдение вместо окончательного завершения.
- Это compatibility/lifecycle patch; нативные ELF не изменялись.

# Список изменений Nfqttl eCubz v15.0.3 (1503)

- Создан скрипт чистой деинсталляции `uninstall.sh`: гарантированный сброс параметров `tether_offload_disabled`, `override_tether_enable_bpf_offload` и `persist.sys.tether.offload.enable` к заводским значениям при удалении модуля.
- Устранена ошибка «Подключено без интернета»: домены проверки связи (Captive Portal / NCSI) в `blocklist.txt` по умолчанию закомментированы, исключая ложную блокировку клиентских устройств (ноутбуков, ПК, телефонов).
- Устранена поломка DNS в стандартной конфигурации: `REDIRECT --to-ports 53` больше не является поведением по умолчанию; экспериментальный redirect остаётся доступен только через отдельный флаг `dns_redirect`.
- Добавлена гарантированная цепочка `nfqttlnat` (NAT MASQUERADE fallback) и `nfqttlfwd` (FORWARD ACCEPT) для стабильной автономной работы точки доступа на чипсетах Qualcomm Snapdragon (включая модемы IPA), MediaTek, Exynos и Google Tensor.
- Реализовано автосохранение исходных системных настроек в `.original.conf` при первом старте.
