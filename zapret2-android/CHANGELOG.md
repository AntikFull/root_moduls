# v3.3.3 (3230) — WARP adaptive/UI recovery fix

- Исправлен вечный статус «Поиск рабочего профиля»: первичный AUTO-поиск теперь завершает всю ограниченную матрицу из 40 кандидатов и явно переходит в `failed`, если handshake не найден. После полного провала действует backoff, а не бесконечная ротация.
- `service-watch.sh` и `vpn-watch.sh` перечитывают `zapret2.conf` во время работы: включение WARP из WebUI после загрузки Android больше не оставляет watcher со старым `ENABLE_WARP=0`.
- Исправлен WebUI live-polling: несохранённые WARP-поля больше не перезаписываются каждые 2.5 секунды. Отдельно отображаются сохранённый baseline и реально тестируемый AUTO-профиль.
- Добавлены режимы `AUTO` и `Ручной`. В ручном режиме Jc/Jmin/Jmax, endpoint/port остаются строго пользовательскими; I1/I2 можно принудительно включить отдельным переключателем.
- AUTO использует конечную матрицу: сначала все 20 BASIC-комбинаций (5 J-профилей × 4 WARP-порта), и только если ни одна не дала handshake — 20 тех же комбинаций с SIP I1/I2. В набор включён совместимый со старыми рабочими конфигами профиль `Jc=10, Jmin≈800, Jmax≈1400` с ограничением Jmax по MTU.
- S1/S2/H1-H4 не рандомизируются для Cloudflare WARP: сохраняются WireGuard-совместимые значения; адаптируются только клиентские junk/signature параметры и endpoint port.
- Сохранение WARP через HTTP/WebRoot больше не ждёт долгий adaptive scan: restart запускается асинхронно, UI получает ответ сразу.
- Усилена генерация WARP peer-конфига: PublicKey пира извлекается из блока peers, с известным consumer-WARP peer key как безопасным fallback; PrivateKey по-прежнему генерируется индивидуально на устройстве и в ZIP не поставляется.
