# Версия v2.3.0

Главное: gateway больше не признатся рабочим только по коду ответа.

- **Проверка страны выхода.** Раньше health-check принимал любой код 200..499, поэтому заблокированный сервер (403 гео-блока) считался рабочим маршрутом. Теперь для Cloudflare-сервисов проверяется страна выхода через `/cdn-cgi/trace`, и gateway с `loc=RU` отбраковывается. Настройка `BLOCKED_LOC` в `install.conf` (по умолчанию `RU`, `off` — отключить).
- **Отбраковка gateway = сам сервис.** Если кандидат совпадает с адресом, который выдат обычный резолвер, это не обход, а прямое подключение к заблокированному серверу. Проверено на живом устройстве: NotebookLM получал реальный IP Google `172.217.118.4` и показывал гео-блок, при этом модуль писал NotebookLM: OK. Теперь выбирается настоящий прокси.
- Эта же ошибка была у ChatGPT: выбирался российский edge Cloudflare `104.18.32.47` (`loc=RU`), статус — «ChatGPT: OK».
- Новая диагностическая команда `aiunblock-native trace -ip IP -domain HOST` — показывает `status` и страну выхода.
- Отчт на `/sdcard` обновляется сразу при смене состояния, а не раз в 10 минут.
- Исправлено: первая попытка зеркалирования логов сразу после загрузки (когда `/sdcard` ещ не смонтирован) съедала весь интервал, и пользователь до 10 минут видел отчт от прошлой версии.

Батчинг проб (нативное ядро):

- Новые команды `probe` и `resolve` делают весь подбор gateway и вс DNS/DoH-обнаружение в одном процессе. Раньше запускался отдельный процесс на каждую пару (IP, домен) и на каждый резолвер  до ~60 стартов Go-рантайма на один неудачный подбор.
- Замер на устройстве: старый способ — 10 запусков процесса за 12 с; новый — та же работа за 4.1 с одним процессом.
- Убрана зависимость от `net/http` (свой разбор ответа с поддержкой Content-Length, chunked и чтения до закрытия) — минус ~330 КБ на каждую ABI.
- `GOMAXPROCS=2` для роутера: меньше потоков и памяти на многоядерных SoC.
- Пакет разделн на файлы с build-тегами, `SO_ORIGINAL_DST` вынесен в `origdst_linux.go`  исходник теперь собирается и проверяется на любой машине разработчика.
- Исправлено: `sha256sum` в бинарном режиме писал имена как `*path`, из-за чего установщик отвергал бинарник. Установщик теперь терпим к обеим формам.
- DoH-запрос явно договаривается об `http/1.1` через ALPN.

Энергопотребление:

- Сторожевой цикл больше не будит CPU каждые 15 секунд: в штатном состоянии пробуждение раз в 120с, 15с остаются только пока есть проблема.
- Пробуждение стало почти бесплатным: чтение PID-файла и проверка роутера идут встроенными средствами шелла, `/proc/PID/cmdline` читается только при смене PID.
- Время считается по `/proc/uptime` (монотонно), а не через запуск `date`  заодно ушл риск, что коррекция часов при загрузке отправит следующую проверку на часы вперд.
- UID приложений берутся из `/data/system/packages.list` одним `awk`; для остальных профилей UID вычисляется как `user*100000+appid`. Раньше на каждую перепроверку запускалось 6–12 процессов `pm` (то есть стартов JVM).
- Установка/удаление приложения отслеживается по метке `packages.list`, поэтому опрос «а не появился ли ChatGPT» больше не нужен.
- Аварийные повторы идут с экспоненциальным откатом 30 → 60 → … → 900с вместо бесконечных попыток раз в 30с.
- Чистка правил старых версий выполняется один раз при старте, а не при каждом обновлении правил (минус десятки вызовов iptables).
- Сканирование чужих firewall-правил (`iptables-save`) — не чаще раза в час и только при наличии целевых UID.
- Зеркалирование логов на `/sdcard`  раз в 10 минут вместо 2 минут; `self-test` нативного ядра для отчта больше не запускается каждый раз, результат кешируется.
- Проверка сети `ip route get`  один процесс вместо трх.

Совместимость с любыми прошивками:

- Отсутствие `xt_comment` в ядре больше не ломает установку хуков — правила ставятся без меток.
- Отсутствие `REJECT` больше не ломает QUIC/fail-правила — автоматически используется `DROP`.
- `timeout`, `pm`, `cmd`, `stat`, `sort`, `wc` стали необязательными: без них модуль деградирует, но работает.
- PATH дополняется системными каталогами, если root-менеджер их не передал.
- Разовый сбой зависимостей (ядро/netd ещ не готовы) больше не убивает супервизор до перезагрузки  10 повторов с паузой.
- Optional hosts на KernelSU/APatch больше не отключается заранее из-за отсутствия metamodule: дерево готовится всегда, а факт монтирования честно проверяется после загрузки (`prepared` → `active` / `not-mounted`).

Исправления:

- Пользовательские `DNS` из `smartdns.user.conf` терялись после первого же `refresh_all` — `load_proxy_config` затирал `AUTH_DNS`.
- Определение пересечения с чужим firewall срабатывало по префиксу UID (`10234` совпадал с `102340`).
- `hosts_log` вызывал системный `/system/bin/log` вместо функции логирования модуля, поэтому сообщения о hosts уходили в logcat, а не в лог модуля.
- Временные каталоги проб (`.probe.*`, `.select.*`, `.doh.*`) после жсткой остановки супервизора оставались навсегда  теперь чистятся при старте.
- `service.sh --signal-refresh/--signal-reload` больше не выполняет версионную очистку логов.

- При обновлении на новую версию полностью удаляются старые внутренние и пользовательские логи.
- `/data/adb/AIUnblock/logs` очищается один раз при первом старте новой версии.
- `/sdcard/eCubz/AIUnblock/logs` полностью пересоздатся при первом доступе к памяти после обновления.
- Удаляются старые `.log`, `.log.1`, `AIUnblock_report.txt`, временные файлы и все старые диагностические `.tar.gz`.
- Очистка привязана к версии и не выполняется при обычной перезагрузке.

- Исправлено получение SO_ORIGINAL_DST для transparent SNI-router на Android/arm64 и остальных ABI: вместо ручных syscall-номеров используется системный Go getsockopt wrapper.
- Неизвестные/нецелевые SNI внутри Google App снова должны уходить на исходный адрес, а не обрываться с `unexpected address family 0`.
- Self-test теперь проверяет декодирование sockaddr_in для transparent pass-through.
- Router-log очищается один раз при смене версии, чтобы ошибки старого бинарника не смешивались с новым релизом.

## Версия v2.3.0-rc4

- `FAIL_MODE` унифицирован с остальными настройками: теперь `0` = direct только при аварии обхода, `1` = block при аварии; старые значения `direct|block` автоматически мигрируют.
- Полностью заменн несовместимый stripped `aiunblock-router`: добавлен открытый `aiunblock-native` с исходником и воспроизводимым build-script.
- Универсальный ZIP содержит четыре ABI: `arm64-v8a`, `armeabi-v7a`, `x86_64`, `x86`; установщик выбирает нужный и запускает self-test до завершения установки.
- Для ARM64 основной native core — корректный Android PIE с `/system/bin/linker64` и `DT_HASH`, плюс статический fallback; ARMv7/x86_64/x86 используют статические pure-Go ELF. Каждый выбранный бинарник проходит on-device self-test до завершения установки, поэтому класс ошибки старого ELF `empty/missing DT_HASH/DT_GNU_HASH` больше не принимается молча.
- Удалн bundled `curl`; TLS gateway probe, DNS-auth и DoH выполняются тем же multi-ABI native core.
- SNI-router сохраняет исходное назначение для unmatched SNI через `SO_ORIGINAL_DST`, а matched SNI остатся fail-closed при отсутствии gateway.
- Если SNI-router падает во время работы, watchdog немедленно пересобирает правила: `FAIL_MODE=0` убирает мртвый redirect, `FAIL_MODE=1` включает аварийную блокировку; при восстановлении router штатные правила возвращаются.
- Диагностика теперь включает native self-test/version, чтобы несовместимость ABI/исполняемого файла была видна прямо в пользовательском архиве.
- Добавлена пассивная проверка пересечения target UID со сторонними firewall/NFQUEUE-правилами (например Zapret2): AIUnblock ничего чужого не удаляет, но предупреждает в `AIUnblock_report.txt` и диагностике.
- Удалн legacy `META-INF/update-binary`, который напрямую требовал Magisk. ZIP теперь рассчитан на установку через Magisk/KernelSU/APatch Manager, где `customize.sh` является штатной точкой кастомизации; recovery-flash не заявляется.
