# Инструкция агента: zygisk_smart_reward_bypass

Читать перед любым изменением в этом каталоге. Полное описание архитектуры —
в [README.md](README.md), раздел 2.

---

## Что это и в каком оно состоянии

Zygisk-модуль: игра считает рекламу готовой, показ подменяется, награда
выдаётся штатным каналом рекламной сети.

Состояние на 20 августа 2026 (v4.1.1): **работает, подтверждено на устройстве.**
Проверено на `com.pockethaven.roguelegend` (AppLovin MAX, Android 16,
KernelSU + ReZygisk): перехват срабатывает, реклама не показывается, монеты
начисляются, цикл повторяется, падений нет.

---

## Суть за один абзац

Игра спрашивает «реклама готова?» — модуль отвечает «да», не доходя до SDK.
Игра говорит «покажи» — модуль не показывает, а сразу выдаёт награду тем
каналом, каким её доставил бы сам SDK. Рекламный SDK при этом не просыпается,
поэтому наличие сети и работа блокировщиков рекламы значения не имеют.

---

## Что проверено, а что нет

| Путь | Состояние |
|---|---|
| Нативные движки (Cocos2d-x), AppLovin MAX | **проверено**: Earn to Die 2, награда начисляется |
| Unity IL2CPP, установка перехватов | **проверено**: перехваты срабатывают, счётчики растут |
| Unity + AppLovin MAX, выдача награды | частично: канал вызывается, полный сценарий не подтверждён |
| Unity, обёртка игры с коллбэком `Action<bool>` | **проверено**: Jewel Hunter (Yandex), награда начисляется |
| Нативное Android-приложение + Yandex SDK | **проверено**: Едадил, Java-слой; экран гасится после открытия |
| Профильные каналы AdMob / Yandex / Unity Ads | **не проверено**: нет подходящих приложений на устройстве |
| armeabi-v7a, x86, x86_64 | **не проверено**: устройство arm64 |

Не переписывать эту таблицу без доказательства. Формулировка «должно работать»
в ней недопустима.

## Грабли этого модуля

1. **Запись в `MethodInfo::methodPointer` не перехватывает вызовы.** Так модуль
   был устроен до 4.1.0: 2702 «установленных» перехвата, ноль срабатываний.
   Перехват — только через `install_detour()`.

2. **Нельзя подменять обёртку игры целиком.** `MobileAdsHandler::ShowRV` и
   подобные готовят своё состояние; подмена роняет игру уже после возврата из
   перехвата. Ограничитель — `is_sdk_show_entry_point()`; ослаблять его нельзя.

3. **AppLovin MAX не использует `UnitySendMessage`.** События идут через
   Java-прокси в `MaxSdkCallbacks.ForwardEvent`. Формат события — плоский
   (`{"name":..,"adUnitId":..,"placement":..}`), вложенный `adInfo` этим
   плагином не разбирается. Эталон — `templates/AppLovin-MAX-Unity-Plugin/.../MaxSdkUnityEditor.cs`.

4. **В нативных движках готовность приходит «наталкиванием».** Игра не
   спрашивает, а ждёт уведомления от Java. Без сети его не будет — модуль шлёт
   уведомление сам. Если кнопка награды не появляется, причина обычно здесь.

5. **Порядок коллбэков при показе.** Сначала начисление, потом закрытие.
   `on_rewarded_video_ad_rewarded` и `on_rewarded_video_ad_closed` неразличимы
   по подстроке `reward` — различать по токенам.

6. **Имена методов обёртки у каждой игры свои.** Списком не задаются, только
   разбором на токены. Новые правила выводить из декомпиляции (`templates/jadx`),
   а не подбирать.

## Известные ограничения

- Перехват с вызовом оригинала не поддерживается — только полная подмена.
- Inline-перехват реализован для arm64 и arm32; на x86/x86_64 не ставится.
- IronSource в Unity остаётся на общем запасном канале, отдельный не сделан.

## Правило номер один

**Установленный перехват и сработавший — разные события.** Сообщение об
установке ничего не доказывает.

Единственное доказательство работоспособности:

```
[HOOK_ACTIVITY] ... | ready: hooks=11 calls=6 | show: hooks=8 calls=4
```

`calls > 0` — работает. `calls = 0` при `hooks > 0` — не работает, что бы ни
писали остальные сообщения.

История вопроса: версии 1.0.0–4.0.5 писали в журнал `[SUCCESS] Patched
methodPointer` и считались рабочими. Замер дал **2702 установленных перехвата и
ноль срабатываний.**

---

## Второе правило: проверять, что библиотека вообще загружается

Неразрешённый символ приводит к тому, что модуль числится включённым, стоит в
списке ReZygisk, но в процесс не попадает ни разу. Именно так версии
4.0.6–4.0.8 «работали» несколько дней.

После любых правок, затрагивающих глобальные переменные, `extern`-объявления
или состав файлов сборки:

```bash
adb shell "su -c 'LD_PRELOAD=/data/adb/modules/zygisk_smart_reward_bypass/zygisk/arm64-v8a.so /system/bin/true'"
```

Молчание — норма. `cannot locate symbol` — модуль мёртв.

Локальная проверка без устройства:

```bash
llvm-nm -u -D zygisk/arm64-v8a.so | grep smartreward   # должно быть пусто
```

## Порядок проверки на устройстве

Пропуск любого шага делает результат недостоверным.

```bash
# 1. Сборка и упаковка
python build_reward_zygisk.py
python ../../pack_module.py .

# 2. Установка
adb push <zip> /data/local/tmp/m.zip
adb shell "su -c 'ksud module install /data/local/tmp/m.zip'"

# 3. ПОЛНАЯ ПЕРЕЗАГРУЗКА — обязательно
adb reboot
```

**Почему именно перезагрузка.** ReZygisk формирует список рабочих модулей один
раз при старте системы. Если на прошлой загрузке библиотека была отбракована,
перезапуск Zygote (`killall zygote`) её не подхватит — модуль останется
невидимым, и вы будете отлаживать призрак.

Перезапуск Zygote допустим только для быстрой итерации по `.so`, когда модуль
уже успешно загрузился на этой загрузке системы.

```bash
# 4. Запуск и наблюдение
adb logcat -c
adb shell am start -n <пакет>/<активность>
adb logcat -d -s SmartReward-Engine:V | grep HOOK_ACTIVITY
```

Перехваты появляются через 8–12 секунд после старта процесса — это выдержка
готовности рантайма, а не задержка.

## Что запрещено

| Запрет | Что случится при нарушении |
|---|---|
| Писать в `MethodInfo::methodPointer` ради перехвата | Перехват не сработает: AOT-код зовёт функцию по адресу напрямую |
| Обращаться к IL2CPP до истечения выдержки | `SIGSEGV` внутри `libil2cpp` на старте игры; падает даже `il2cpp_domain_get()` |
| Подменять методы показа в `Assembly-CSharp` | Игра теряет своё состояние и падает после возврата из перехвата |
| Приводить `methodPointer` к предполагаемому типу функции | Порча регистров. Только `il2cpp_runtime_invoke` |
| Подставлять константу в делегат со ссылочным параметром | Игра получит указатель `0x1` и упадёт при обращении к полю |
| Делать файловые операции в теле перехвата | Перехват идёт на главном потоке игры: фризы и ANR |
| Зашивать числовые константы SDK | Ломается на другой версии SDK. Читать из метаданных игры |
| Брать формат события SDK по памяти | Событие уходит в пустоту. Сверять с исходниками в `templates/` |

| Файл | Ответственность |

## Как добавить поддержку новой рекламной сети

1. Найти **исходники Unity-плагина** сети. Java-SDK из `SUPERmodul/sourse/` для
   этого не годится: там нет C#-стороны, которая и определяет формат событий.
   Уже есть: `templates/AppLovin-MAX-Unity-Plugin`,
   `templates/googleads-mobile-unity`, `templates/YandexMobileAds-Unity`.
2. Определить **семейство доставки**:
   - статическая шина строк (вызвать статический метод с сообщением);
   - события на объекте (прочитать поле-делегат, создать аргумент, вызвать);
   - слушатель или делегат в аргументах вызова.
3. Добавить обработчик в `reward_channels.cpp`, опираясь на
   `ManagedInvoker`. Константы перечислений — только чтением из метаданных.
4. Добавить правила в `il2cpp_hooks.conf` **только для точек входа SDK**.
5. При необходимости внести класс в `is_sdk_show_entry_point()`.
6. Проверить на устройстве по порядку выше и убедиться, что `calls > 0` и
   награда реально начислилась в игре.
