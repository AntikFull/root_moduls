# Changelog

## v4.3.2 (433)

### Оптимизация энергопотребления и UFS: отключение фонового logcat по умолчанию

- Фоновый процесс сбора `logcat` в `runtime.log` переведен в режим по требованию. Постоянный сброс буфера на накопитель создавал избыточный I/O и препятствовал переходу флеш-памяти (UFS) и шин в режимы глубокого сна.
- По умолчанию логирование в файл отключено. Сам перехват и начисление наград работают автономно в адресном пространстве целевых процессов игр без участия демона logcat.
- Включение журнала отладки при необходимости:
  - Созданием файла `/data/adb/zygisk_smart_reward_bypass/debug`
  - Либо установкой параметра `ENABLE_LOGCAT=1` в `/data/adb/zygisk_smart_reward_bypass/reporting.conf`
- В `service.sh` добавлено корректное завершение устаревшего процесса при отключенном режиме отладки.

## v4.3.0 (430)

### Подмена обёртки приложения разрешена при наличии коллбэка завершения

Прежнее правило запрещало подменять методы показа в коде приложения целиком —
после падения Rogue Legend, где подмена оставляла игру с неинициализированными
полями. Ограничение оказалось слишком широким: значительная часть игр вообще не
обращается к SDK напрямую, а вызывает собственную обёртку, **передавая ей
продолжение аргументом**.

Пример из Jewel Hunter (Unity + Yandex через обёртку Gley Mobile Ads):

```
Assembly-CSharp.dll | YandexAdsManager::ShowRewardedVideo | params ['System.Action<System.Boolean>']
```

Здесь подмена безопасна: продолжение игры приходит аргументом, и модуль вызывает
его сам — состояние не теряется. Правило уточнено: обёртка приложения
подменяется, только если среди аргументов есть делегат, который модуль умеет
корректно вызвать (`System.Action` или `Action<простой значимый тип>`). Без
такого делегата подмена по-прежнему запрещена — случай Rogue Legend остаётся
закрытым.

Добавлены общие правила показа для любого класса
(`*::*ShowRewardedVideo*`, `*::*ShowRewardedAd*`, `*::*ShowRewarded*`,
`*::*ShowVideoAd*`). Безопасность обеспечивается не списком классов, а проверкой
сигнатуры.

### Проверено на устройстве

| Сценарий | Приложение | Результат |
|---|---|---|
| Unity, обёртка с коллбэком, Yandex | Jewel Hunter | награда начисляется, показа нет, падений нет |
| Нативный движок Cocos2d-x, AppLovin MAX | Earn to Die 2 | награда начисляется, показа нет |
| Нативное Android-приложение, Yandex SDK | Едадил | награда начисляется (Java-слой, экран гасится после открытия) |

В Jewel Hunter награду доставил универсальный канал — вызов делегата завершения
из аргументов (`[CHANNELS] Награда выдана через делегат завершения`).
Профильный канал Yandex (события `RewardedAd.OnRewarded`) корректно отступил:
игра работает через обёртку и на события SDK не подписана.

### Что по-прежнему не проверено

- Профильные каналы Yandex, Google Mobile Ads и Unity Ads в чистом виде.
  Приложений с прямым использованием этих Unity-плагинов без обёртки на тестовом
  устройстве нет. Unity Ads не установлен ни в одном приложении.
- Сборки `armeabi-v7a`, `x86`, `x86_64`.


## v4.2.0 (420)

### Первая версия, проверенная на устройстве от нажатия до начисления

Проверено на OnePlus PJA110, Android 16, KernelSU Next + ReZygisk,
игра Earn to Die 2 (Cocos2d-x, AppLovin MAX). Полная цепочка в журнале:

```
Рекламная обёртка игры: com.notdoppler.advertising.MAXHelper
Показ рекламы: MAXHelper.showRewardedVideo -> подмена на выдачу награды
Начисление награды: on_rewarded_video_ad_rewarded
Закрытие рекламного экрана: on_rewarded_video_ad_closed
Уведомление игры о доступности рекламы: on_rewarded_video_availability_changed
```

Награда начислена в игре, рекламный экран не показывался, приложение не падало.

### Исправлена сборка релиза

Предыдущие архивы собирались с пересборкой только arm64: библиотеки
`armeabi-v7a`, `x86` и `x86_64` попадали в архив от более ранней версии и не
содержали исправлений. Теперь релиз собирается по всем architectures разом, а
совпадение содержимого архива с собранными файлами проверяется перед упаковкой.


## v4.1.3 (413)

### Классификация Java-методов переписана по разбору имени на токены

Прежние правила подбирались по вхождению подстроки и не совпадали ни с одним
реальным методом в разобранных играх. Имя метода теперь разбирается на токены
(по подчёркиванию и смене регистра), решение принимается по составу токенов.

Правила построены на декомпилированном коде двух игр:

| Игра | Готовность | Показ | Награда |
|---|---|---|---|
| Earn to Die 2 (Cocos2d-x) | `on_rewarded_video_availability_changed(boolean)` | `showRewardedVideo(String)`, void | `on_rewarded_video_ad_rewarded()` |
| Kingdom Rush (LOVE 2D) | `hasVideoAd(String)`, boolean | `createRequestShowVideoAd(String)`, **int** | статус запроса `getRequestStatus(id)` = 0 |

Что было исправлено:

- **Уведомление о доступности принимает аргумент** `boolean`. Прежний код искал
  только методы без аргументов и поэтому не находил его никогда.
- **Метод начисления награды различается по последнему токену.** В обёртке есть
  и `on_rewarded_video_ad_rewarded`, и `on_rewarded_video_ad_closed`; оба
  содержат слово `rewarded`, и по подстроке они неразличимы. Прежний код
  вызывал только закрытие, оставляя игрока без награды.
- **Добавлен перехват методов, возвращающих int.** Модель «создать запрос на
  показ и опрашивать его статус» им не покрывалась вовсе. Модуль возвращает
  собственный номер запроса и отвечает на опрос по нему «успешно завершён».
- **Запрос готовности вида `hasVideoAd`** теперь распознаётся: токен `has`
  добавлен в признаки запроса состояния.

### Проверка

Классификатор построен на декомпилированном коде игр, а не на подборе шаблонов.
Для разбора APK в `templates/jadx` добавлен декомпилятор.


## v4.1.2 (412)

### Поддержка игр на нативных движках (Cocos2d-x, LOVE 2D, Unreal)

Игры не на Unity не содержат C#-кода: рекламная логика у них расположена в Java,
а игровой код на C++ обращается к ней через JNI. Перехват IL2CPP к ним
неприменим, поэтому добавлен отдельный слой.

- **Перехват границы «нативный код -> Java»** (`core/jni_bridge_hook.cpp`).
  Таблица функций JNI — это массив указателей; подмена нескольких записей даёт
  контроль над каждым вызовом Java-метода из нативного кода. Инлайн-перехват и
  фреймворки перехвата методов ART для этого не требуются.
- **Оповещение о готовности рекламы.** В таких играх готовность работает не
  запросом, а сообщением: Java уведомляет игровой код о загрузке рекламы. Без
  сети уведомление не приходит никогда, и кнопка награды не появляется.
  Модуль находит в рекламной обёртке приложения метод уведомления и вызывает
  его сам.
- **Выдача награды** выполняется вызовом наградных коллбэков той же обёртки,
  строго по порядку: сначала начисление, затем закрытие экрана. Вызов только
  закрытия оставлял игрока без награды.
- Имена методов не задаются списком заранее: они находятся по метаданным
  классов приложения.

### Ограничение области действия

- Перехват ставится **только** в процессах, где действительно присутствует
  рекламный SDK, и применяется **только** к классам из пространства имён самого
  приложения. Внутренние вызовы рекламных SDK, системных библиотек и движка
  браузера проходят без изменений.
- Исправлено ложное срабатывание фильтра: слово `ready` само содержит `ad`,
  из-за чего под правило попадал любой метод со словом ready (обнаружено на
  `org.chromium...WatcherImpl.onHandleReady`). Признак рекламного контекста
  сужен до однозначных слов.
- В список жёстко защищённых процессов добавлены `com.qti.*` и `org.chromium.*`.

### Известные ограничения

- Слой JNI на устройстве проверен частично: перехват показа и вызов коллбэков
  подтверждены, полный цикл с начислением награды в игре на Cocos2d-x на момент
  выпуска не подтверждён.


## v4.1.1 (411)

### Выдержка перенесена до первого обращения к рантайму Unity

- Небезопасным оказался не только обход метаданных, но и сам вызов
  `il2cpp_domain_get()`: пока выполняется `il2cpp_init`, он разыменовывает ещё
  не созданные внутренние структуры. Подтверждено разбором tombstone: падение
  `SIGSEGV` по адресу `0x135` внутри `libil2cpp.so` через 246 мс после появления
  библиотеки, вызов пришёл из `il2cpp_api.cpp:1201`.
  Отсчёт выдержки перенесён на момент, когда `libil2cpp.so` впервые доступна для
  `dlsym`; до её истечения в рантайм не делается ни одного вызова.
  Проверено: три запуска игры подряд без падений.

### Отладка сборки

- Сборка сохраняет копию библиотеки с таблицей символов в `.build/symbols/`
  до удаления символов из поставляемого файла. Адреса при этом не меняются,
  поэтому смещение из tombstone восстанавливается в имя функции и строку
  исходника. Размер и содержимое поставляемой библиотеки не изменились
  (проверено совпадением SHA-256).

### Подтверждено на устройстве

Полный цикл на `com.pockethaven.roguelegend` (AppLovin MAX, Android 16,
KernelSU + ReZygisk): перехват готовности и показа срабатывает, реклама не
показывается, награда начисляется, реклама сразу снова готова, цикл
повторяется. Падений и зависаний нет.


## v4.1.0 (410)

### Модуль снова загружается (версии 4.0.6–4.0.8 не работали вообще)

- **Исправлена ошибка линковки, из-за которой библиотеку невозможно было загрузить.**
  `applovin_adapter.cpp` обращался по `extern` к `g_state_mutex` и
  `g_captured_ad_unit_id`, которые были объявлены в анонимном пространстве имён
  `il2cpp_api.cpp` и наружу не экспортировались. Динамический загрузчик
  отвергал библиотеку целиком:
  `cannot locate symbol "_ZN11smartreward13g_state_mutexE"`.
  Проверено на устройстве: до исправления модуль числился включённым и
  отображался в списке ReZygisk, но в процесс приложения не попадал ни разу.
  Дефект присутствовал в 4.0.6, 4.0.7 и 4.0.8; версии до 4.0.5 включительно
  загружались.

### Перехват IL2CPP заменён на работающий механизм

- **Вместо записи в `MethodInfo::methodPointer` применяется inline-перехват.**
  В скомпилированном заранее коде IL2CPP вызовы C#-методов адресуются напрямую,
  и поле `methodPointer` при обычном вызове не читается — оно задействовано лишь
  на путях рефлексии, при создании делегатов и при построении таблиц виртуальных
  методов. Поэтому прежний способ фиксировал «перехват установлен», но
  фактически не срабатывал: в журналах устройства 2702 установленных перехвата
  и ноль вызовов.
  Теперь в начало целевой функции записывается одна инструкция перехода на
  переходник, размещённый рядом в пределах досягаемости. Патч в 4 байта по
  выровненному адресу атомарен относительно выборки инструкций, поэтому
  перехват безопасно ставится и на выполняющуюся функцию.
- **Добавлены счётчики фактических срабатываний** (`[HOOK_ACTIVITY]`).
  Установка перехвата и его выполнение теперь различимы: на горячем пути
  выполняется единственный атомарный инкремент, сводка печатается фоновым
  потоком и только при изменении показаний.

### Устранены источники падений и зависаний

- **Барьер готовности рантайма Unity.** Обход метаданных и присоединение потока
  к сборщику мусора выполнялись через 200 мс после старта процесса, когда
  `il2cpp_init` ещё не завершился, что приводило к `abort()` внутри libil2cpp
  на этапе загрузки игры. Теперь работа с рантаймом начинается только после
  выдержки и стабилизации числа загруженных сборок.
- **Сужена область сканирования метаданных.** Системные сборки .NET и внутренние
  модули движка (`UnityEngine.*Module.dll`) исключены: их обход вынуждал рантайм
  материализовать десятки тысяч классов и конкурировал с главным потоком за
  блокировки метаданных.
- **Скрытый аргумент `MethodInfo*` исключён из разбора.** IL2CPP добавляет его
  последним параметром каждой сгенерированной функции. Трамплин принимал его за
  строку или делегат и читал код как данные, что давало `SIGSEGV`.
- **Подмена показа применяется только к точкам входа рекламных SDK.**
  Внутренние обёртки игры (`Assembly-CSharp`) больше не заменяются: помимо
  вызова SDK они готовят собственное состояние, и их подмена оставляла игру с
  неинициализированными полями. Подтверждено падение Rogue Legend при подмене
  `MobileAdsHandler::ShowRV`.
- **Безопасный вызов делегатов.** Прежде первым аргументом всегда подставлялась
  единица. Для `Action<bool>` это корректно, но для делегата со ссылочным
  параметром (`Action<Reward>`, `Action<AdInfo>`) игра получала указатель `0x1`.
  Теперь тип параметра проверяется по метаданным, и значение синтезируется
  только для простых значимых типов.
- **Запись отчёта вынесена с горячего пути.** Пересборка профиля читала весь
  журнал событий и переписывала многомегабайтный файл с `fsync` прямо в теле
  перехвата на главном потоке игры. Теперь задача ставится в очередь, а диском
  занимается фоновый поток; журнал событий ротируется по достижении 2 МБ.

### Доставка наград приведена в соответствие с реальными SDK

- **AppLovin MAX.** Плагин доставляет события через Java-прокси
  (`MaxUnityAdManager$BackgroundCallback` → `MaxSdkBase.HandleBackgroundCallback`
  → `MaxSdkCallbacks.ForwardEvent`) и **не использует `UnitySendMessage`**,
  которым модуль пытался слать награды. Добавлен нативный вызов
  `MaxSdkCallbacks::ForwardEvent` с последовательностью событий показа, награды
  и закрытия. Формат события сверен с эталонной заглушкой плагина
  `MaxSdkUnityEditor.cs`; прежняя вложенная структура `adInfo` этим плагином не
  разбирается.
- **Google Mobile Ads (AdMob).** Награда выдаётся вызовом `Action<Reward>`,
  переданного аргументом в `Show`, с корректно созданным объектом `Reward`.
  Дополнительно поднимаются `OnAdFullScreenContentOpened` и
  `OnAdFullScreenContentClosed`, по которым игры закрывают свой интерфейс.
- **Yandex Mobile Ads.** Награда доставляется через события самого объекта
  (`RewardedAd.OnRewarded`), а не через общую шину, которой у этой сети нет.
- **Unity Ads.** Вызывается `OnUnityAdsShowComplete` у слушателя, переданного
  в `Show`. Значение состояния `COMPLETED` читается из метаданных загруженной
  версии SDK, а не зашито числом.
- **Общий запасной путь** — вызов делегата завершения из аргументов, если
  профильный канал сети не определён.
- Все обращения к управляемому коду выполняются через штатный
  `il2cpp_runtime_invoke`, который сам подбирает корректное соглашение о вызове.

### Известные ограничения

- Перехват с вызовом оригинала не поддерживается: механизм рассчитан на полную
  подмену. Действие `forward_interceptor` отключено; при работающем перехвате
  готовности и показа оно не требуется, так как SDK не доходит до сетевых
  запросов и не порождает событий отказа.
- Каналы Yandex, Unity Ads и Google Mobile Ads собраны по исходникам
  соответствующих Unity-плагинов, но на устройстве пока не проверены.
  Проверен канал AppLovin MAX.
- Inline-перехват реализован для arm64 и arm32. Для x86/x86_64 (эмуляторы)
  перехват не устанавливается.
