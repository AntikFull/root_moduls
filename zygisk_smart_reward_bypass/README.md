# Zygisk — Smart Reward & Ad Bypass

Zygisk-модуль: игра считает рекламу всегда загруженной и готовой, показ рекламы
не происходит, награда начисляется сразу.

Автор: eCubz (https://t.me/eCubz) · Поддержка: https://t.me/module_ecubz

---

## 1. Что именно делает модуль

Две вещи, и обе — до того, как рекламный SDK успевает вмешаться:

1. **Отвечает «реклама готова»** на любой вопрос игры о готовности рекламы.
2. **Перехватывает показ**: реклама не показывается, а игре немедленно
   отправляется штатное событие «награда получена» тем же каналом, каким его
   доставил бы сам SDK.

Поддержаны два вида игр: на Unity (перехват внутри IL2CPP, раздел 2.1–2.4) и на
нативных движках вроде Cocos2d-x, LOVE 2D, Unreal (перехват границы с Java,
раздел 2.5).

Из этого следует важное свойство: **блокировка рекламы другими средствами не
мешает и не помогает.** AAD, hosts-файл, фаервол, отключённые рекламные Activity
— всё это работает *ниже* нашего перехвата. Игра до сетевого слоя не доходит.
Отсутствие интернета тоже не мешает.

## 2. Как это устроено

### 2.1 Перехват: почему inline, а не подмена указателя

Код Unity-игры компилируется заранее (AOT). Вызов C#-метода в скомпилированном
коде адресуется **напрямую по адресу функции**. Поле `MethodInfo::methodPointer`
при обычном вызове не читается — оно задействовано только на путях рефлексии,
при создании делегатов и при построении таблиц виртуальных методов.

Поэтому запись в `methodPointer` **не перехватывает вызовы**. Это была причина,
по которой модуль до версии 4.1.0 не работал: журналы показывали 2702
установленных перехвата и **ноль** срабатываний.

Работающий механизм — `jni/core/inline_hook.cpp`:

```
       было (не работает)                 стало (работает)
  ┌──────────────────────┐          ┌──────────────────────┐
  │ MethodInfo           │          │ тело функции         │
  │   methodPointer ─────┼─→ наш    │   B  →  переходник ──┼─→ наш код
  └──────────────────────┘   код    │   ...                │
     игра сюда не смотрит           └──────────────────────┘
                                       игра идёт именно сюда
```

В начало целевой функции пишется **одна инструкция перехода** (4 байта) на
переходник, размещённый рядом в пределах досягаемости команды перехода.
Переходник содержит абсолютный переход на наш обработчик.

Почему так, а не 16-байтовая заплата напрямую:

- Патч в 4 байта по выровненному адресу **атомарен** относительно выборки
  инструкций. Перехват безопасно ставится даже на функцию, которая выполняется
  прямо сейчас.
- Короткие функции (например, геттер из двух инструкций) не затираются вместе
  с соседней функцией.

Оригинал не сохраняется: механизм рассчитан на полную подмену. Для задач модуля
вызывать исходный код не требуется.

### 2.2 Где ставится перехват, а где — категорически нет

| Что перехватываем | Действие | Почему безопасно |
|---|---|---|
| Проверки готовности (`IsReady`, `CanShowAd`, `IsRvReady`) — где угодно, включая код игры | `always_true` | Чистый запрос без побочных эффектов |
| Показ и загрузка — **только точки входа рекламных SDK** | `show_and_reward` | Это тонкие мосты к нативному SDK |
| Показ в обёртке игры, принимающей коллбэк завершения аргументом | `show_and_reward` | Продолжение игры вызываем сами |
| Показ в обёртке игры **без** коллбэка в аргументах | **не перехватываем** | См. ниже |

**Почему нельзя подменять обёртки игры.** Метод вроде
`MobileAdsHandler::ShowRV` помимо вызова SDK готовит собственное состояние:
сохраняет коллбэк, ставит флаги, открывает интерфейс. Подмена оставляет игру с
неинициализированными полями, и она падает уже после возврата из перехвата
(подтверждено падением Rogue Legend). Правильный порядок: обёртка игры
отрабатывает как обычно и зовёт SDK — там мы её и встречаем.

Проверка реализована в `hook_method_show_and_reward()`. Обёртка приложения
подменяется только при наличии среди аргументов делегата, который модуль умеет
корректно вызвать (`System.Action` или `Action<простой значимый тип>`) — тогда
продолжение игры выполняется нами и состояние не теряется. Без такого делегата
подмена запрещена.

Именно так работает значительная часть игр: они не обращаются к SDK напрямую, а
зовут собственную обёртку, передавая ей продолжение. Пример из Jewel Hunter:
`YandexAdsManager::ShowRewardedVideo(System.Action<System.Boolean>)`.

### 2.3 Доставка награды: почему нужен канал под каждую сеть

Единого способа сказать игре «награда получена» не существует. Каждая сеть
уведомляет игру по-своему — это устройство SDK, а не недоработка модуля.

| Сеть | Канал доставки | Реализация | Проверено на устройстве |
|---|---|---|---|
| AppLovin MAX | статическая шина: `MaxSdkCallbacks.ForwardEvent(json)` | `adapters/max_bridge.cpp` | **да** |
| Google AdMob | `Action<Reward>` из аргументов `Show` + события открытия/закрытия | `adapters/reward_channels.cpp` | нет |
| Yandex | события объекта: `RewardedAd.OnRewarded` | `adapters/reward_channels.cpp` | нет |
| Unity Ads | `OnUnityAdsShowComplete` у слушателя из аргументов | `adapters/reward_channels.cpp` | нет |
| прочее (Unity) | вызов делегата завершения из аргументов | `deliver_argument_delegates` | нет |
| любая сеть в играх на нативных движках | коллбэки Java-обёртки игры | `core/jni_bridge_hook.cpp` | **да** (Earn to Die 2) |
| обёртка приложения с коллбэком в аргументах | вызов делегата завершения | `deliver_argument_delegates` | **да** (Jewel Hunter) |

Отдельно стоит запомнить: **AppLovin MAX не использует `UnitySendMessage`.**
События идут через Java-прокси
(`MaxUnityAdManager$BackgroundCallback` → `MaxSdkBase.HandleBackgroundCallback`
→ `MaxSdkCallbacks.ForwardEvent`). Попытки слать награды через
`UnitySendMessage` уходили в пустоту — это была вторая причина, по которой
награды не начислялись.

Форматы событий сверены с исходниками плагинов в `templates/`, а не взяты по
памяти. Эталон для MAX — штатная заглушка плагина `MaxSdkUnityEditor.cs`.

### 2.4 Вызов C#-кода

Все обращения к управляемому коду идут через штатный `il2cpp_runtime_invoke`
(`runtimes/il2cpp/managed_invoker.cpp`). Рантайм сам подбирает корректное
соглашение о вызове. Ручное приведение `methodPointer` к предполагаемому типу
функции запрещено: любая ошибка в типах аргументов портит регистры и роняет
процесс.

Числовые константы SDK (значения перечислений) **не зашиты** в модуль — они
читаются из метаданных той версии сборки, которая загружена в конкретную игру.

### 2.5 Игры на нативных движках (Cocos2d-x, LOVE 2D, Unreal)

В Unity логика игры живёт в C#, и перехват ставится внутри IL2CPP. В играх на
нативных движках логика — это сам C++, а реклама доступна ему через тонкую
Java-обёртку, которую пишет разработчик игры. Например, в Earn to Die 2 это
`com.notdoppler.advertising.MAXHelper`.

Перехватывается **граница между нативным кодом и Java** (`jni/core/jni_bridge_hook.cpp`):
вызовы вида `CallStaticVoidMethod`, `CallBooleanMethod`, `CallIntMethod` из кода
игры в её собственные Java-классы.

Обёртка всегда своя у каждой игры, поэтому имена методов не могут быть заданы
списком. Модуль разбирает имя на токены (по подчёркиванию и смене регистра) и
принимает решение по их составу.

**Готовность работает в двух противоположных моделях, и обе нужно поддержать:**

| Модель | Как выглядит | Что делает модуль |
|---|---|---|
| Запрос (pull) | C++ спрашивает Java: `hasVideoAd(placement)` → `boolean` | Отвечает «да» |
| Оповещение (push) | Java сообщает C++: `on_rewarded_video_availability_changed(true)` | **Отправляет оповещение сам** |

Вторая модель — причина, по которой кнопка награды может вообще не появляться:
без сети SDK никогда не сообщит о загрузке, и игра не покажет кнопку. Спрашивать
у игры нечего — надо самому отправить ей это сообщение. Модуль делает это
периодически, пока приложение живо.

**Порядок вызова коллбэков при показе критичен.** В обёртке обычно есть и
`on_rewarded_video_ad_rewarded`, и `on_rewarded_video_ad_closed`. Оба содержат
слово `rewarded`, и по вхождению подстроки они неразличимы — ровно на этом
модуль ранее вызывал только закрытие, и игрок оставался без награды. Правильная
последовательность:

```
showRewardedVideo  →  перехват (реклама не показывается)
                      1. начисление: on_rewarded_video_ad_rewarded
                      2. закрытие:   on_rewarded_video_ad_closed
                      3. повторное оповещение о готовности (перезарядка)
```

Отдельно поддержана модель «создать запрос и опрашивать статус»
(Kingdom Rush: `createRequestShowVideoAd(placement)` → `int`, затем
`getRequestStatus(id)`): модуль возвращает собственный номер запроса и на опрос
по нему отвечает «успешно завершён».

Проверено на устройстве: Earn to Die 2 (Cocos2d-x + AppLovin MAX) — награда
начисляется, рекламный экран не показывается, падений нет.

### 2.6 Порядок запуска

```
процесс приложения
  └─ проверка списка целей (smart_reward.list)
      ├─ Java-ядро: загрузка DEX в память, прокси рекламных SDK
      └─ поток разведки движка
          ├─ ждём появления libil2cpp.so
          ├─ ВЫДЕРЖКА 5 с  ← до неё в рантайм не делается ни одного вызова
          ├─ ждём стабилизации числа загруженных сборок
          ├─ строим индекс метаданных (без системных сборок и модулей движка)
          ├─ привязываем каналы наград
          ├─ ставим перехваты по правилам il2cpp_hooks.conf
          └─ раз в 30 с печатаем сводку срабатываний
```

**Выдержка обязательна.** Пока выполняется `il2cpp_init`, небезопасен даже
вызов `il2cpp_domain_get()` — он разыменовывает ещё не созданные структуры.
Подтверждено падением `SIGSEGV` по адресу `0x135` через 246 мс после появления
библиотеки.

## 3. Диагностика

### Главный вопрос: перехват сработал или только установлен?

Это разные вещи, и путать их нельзя. Смотреть нужно строки `HOOK_ACTIVITY`:

```
[HOOK_ACTIVITY] detours=19 islands=1 slots=19 | ready: hooks=11 calls=6 | show: hooks=8 calls=4
[HOOK_ACTIVITY]   READY  MaxSdkAndroid::IsRewardedAdReady   calls=4
[HOOK_ACTIVITY]   SHOW   MaxSdkAndroid::ShowRewardedAd      calls=2
```

- `hooks=N` — сколько перехватов установлено.
- `calls=N` — **сколько раз они реально выполнились.**

`calls=0` при `hooks>0` означает, что перехват не работает, независимо от того,
что пишут сообщения об установке.

### Команды

```bash
adb logcat -s SmartReward-Engine:V SmartReward-Java:V
```

Ключевые метки:

| Метка | Значение |
|---|---|
| `[INJECT]` | модуль внедрился в процесс |
| `[MANAGED]` | доступен вызов управляемого кода |
| `[MAX_BRIDGE]` | привязка к каналу AppLovin MAX, захват рекламных блоков |
| `[CHANNELS]` | доставка награды профильным каналом сети |
| `[HOOK_ACTIVITY]` | сводка установленных и сработавших перехватов |
| `[HOOK-SKIP]` | перехват не поставлен, с причиной |
| `[IL2CPP_MISS]` | правило не нашло совпадений (обычно норма: этой сети в игре нет) |

### Если модуль вообще не подаёт признаков жизни

Первым делом проверить, что библиотека загружается. Неразрешённый символ
приводит к тому, что модуль числится включённым, отображается в списке, но в
процесс не попадает **никогда**:

```bash
adb shell "su -c 'LD_PRELOAD=/data/adb/modules/zygisk_smart_reward_bypass/zygisk/arm64-v8a.so /system/bin/true'"
```

Молчание — норма. `cannot locate symbol` — модуль не работает вообще.

### Разбор падения

Сборка сохраняет копию с таблицей символов в `.build/symbols/`. Смещения при
удалении символов не меняются, поэтому адрес из tombstone превращается в строку
исходника:

```bash
llvm-addr2line -f -C -i -e .build/symbols/arm64-v8a.so 0x5f8d8
```

## 4. Конфигурация

| Файл | Назначение |
|---|---|
| `/data/adb/zygisk_smart_reward_bypass/smart_reward.list` | целевые пакеты; `*` — все пользовательские приложения; `!пакет` — исключение |
| `/data/adb/zygisk_smart_reward_bypass/il2cpp_hooks.conf` | правила перехвата |
| `/data/adb/zygisk_smart_reward_bypass/logs/runtime.log` | отладочный журнал (активен только при включенном флаге `debug`) |
| `/data/adb/zygisk_smart_reward_bypass/debug` | файл-триггер включения сбора журнала (для экономии батареи по умолчанию отключен) |

Формат правила:

```
[Сборка.dll|]Пространство.Класс::Метод|действие|число_аргументов
```

`*` и `?` — подстановки, `-1` — любое число аргументов.

| Действие | Смысл |
|---|---|
| `always_true` | вернуть `true` (только для методов с типом возврата `bool`) |
| `show_and_reward` | подменить показ или загрузку и выдать награду |
| `resolve` / `observe` | только найти и записать в журнал, без изменений |

Браузеры, мессенджеры, банковские и государственные приложения защищены
жёстко в коде (`core/target_filter.cpp`) и не перехватываются даже при `*`.

## 5. Сборка

```bash
python build_reward_zygisk.py              # все ABI
python build_reward_zygisk.py --abi arm64-v8a
python pack_module.py module/zygisk_smart_reward_bypass
```

Требуется Android NDK, JDK и `d8` из Android SDK — обнаруживаются автоматически.
Версия берётся **только** из `module.prop` и подставляется в остальные файлы.

## 6. Ограничения

- Перехват с вызовом оригинала не поддерживается — механизм рассчитан на полную
  подмену. Действие `forward_interceptor` отключено; при работающем перехвате
  готовности и показа оно не нужно, так как SDK не доходит до сетевых запросов.
- Inline-перехват реализован для `arm64-v8a` и `armeabi-v7a`. Для `x86`/`x86_64`
  (эмуляторы) перехват не устанавливается.
- Каналы Yandex, Unity Ads и Google AdMob собраны по исходникам плагинов, но на
  устройстве не проверялись. Проверен канал AppLovin MAX.
- Игры не на Unity IL2CPP обслуживаются только Java-слоем.

## 7. Правила внесения изменений

Нарушение любого из пунктов уже приводило к неработающему или падающему модулю.

1. **Не заявлять, что перехват работает, без `calls>0` в `HOOK_ACTIVITY`.**
2. **Проверять загрузку библиотеки** (`LD_PRELOAD`-тест) после любых правок,
   затрагивающих глобальные переменные и линковку.
3. **Не обращаться к рантайму IL2CPP до истечения выдержки.**
4. **Не подменять методы показа во внутренних обёртках игры.**
5. **Не выполнять файловых операций на горячем пути.** Перехват выполняется на
   главном потоке игры; запись отчёта ставится в очередь фонового потока.
6. **Не синтезировать аргументы ссылочных типов.** Подставлять значения можно
   только для простых значимых типов; иначе игра получит невалидный указатель.
7. **Форматы событий SDK брать из исходников плагинов**, а не по памяти.
8. **После замены `.so` на устройстве — полная перезагрузка.** Список рабочих
   модулей ReZygisk формирует один раз при старте системы; перезапуска Zygote
   недостаточно, если на прошлой загрузке библиотека была отбракована.
